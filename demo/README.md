# Bounded resume demo

The demo proves a handoff actually lets work resume. It does not describe
resuming. It resumes, once, within strict bounds.

## The full loop

1. A bundle describes one interrupted agent job: events, artifacts,
   receipts, approvals. See `../src/baton/fixtures/`.
2. Baton runs the bundle through the pipeline: validate, deterministic
   checks, extraction, persist. The output is a recovery record, exported
   as `handoff.json`.
3. The resume script (`resume.py`) reads that handoff, takes its Next step,
   performs exactly one bounded action, and verifies the action completed.
4. The verification is a fresh read of the result, not trust in the print
   statement. If verification fails, the script exits non-zero and removes
   the partial output.

## What "bounded" means

- One step. The script performs a single action from a small registry of
  known bounded actions. It never chains steps, never retries with a new
  plan, never improvises.
- Small scope. The one known action writes a report file to a directory.
  It sends nothing, deletes nothing, and touches no other file.
- Verifiable outcome. After acting, the script re-reads its own output and
  checks it names the record, lists the completed work, and states it was
  not sent. A failed check is a failed run.
- Refusal by default. A handoff whose Next step is not a recognized bounded
  action is refused, with no action taken. Unknown means no.

## Run the demo (offline)

From the repo root:

```bash
python3 demo/resume.py web/data/completed-unreported.json --out-dir /tmp/resume-out
```

Expected: exit 0, one report file in `/tmp/resume-out`, and a verification
line. The other two proof cases refuse, because their Next steps need a
human (an approval decision, a delivery check), and those are not bounded
actions this script may take:

```bash
python3 demo/resume.py web/data/never-executed.json --out-dir /tmp/resume-out
python3 demo/resume.py web/data/accepted-unknown.json --out-dir /tmp/resume-out
```

Both exit non-zero with a refusal line and write nothing.

## What the demo consumes

The demo reads a precomputed handoff from `../web/data/`. Those handoffs
were generated by the scaffold pipeline with stub extraction: offline,
deterministic, no live model call. The demo itself makes no network calls
and needs no API key.

Live extraction is proven separately. The Nebius adapter is wired in
`src/baton/nebius.py`, verified against the real model on a real fixture.
The demo does not re-prove it. It proves the handoff is actionable.

## The one known action

Next step `Report the completed work to the user.` maps to writing a
report file from the handoff Completed section. The report states it was
written by the resume demo and was not sent anywhere. Reporting means
writing the file. It does not mean sending.
